# Prioritized backlog

## Release gates

1. Apply cloud network settings, supply the Supabase public project URL and hosting account, and securely bind billed Gemini and managed Supabase credentials. Review current paid data policies and verify exact model IDs/rates.
2. Apply managed migrations, configure production recovery/confirmation email and HTTPS redirects, deploy the real app and scheduler, inspect runtime logs, and prove signup → agent → real reply → refresh. No “finished” label before this passes.
3. Complete hosted two-account isolation, quotas, kill switch, cancellation, document citations, personality/factual standards, and permission-revocation acceptance. Reconcile measured usage with provider billing.
4. Test the voice pipeline with the actual speech provider on iPhone Safari and Android Chrome. Verify turn detection, mute/stop, background/screen lock, voice stability, supported formats, latency and billed-call counts before enabling it.
5. Verify permitted Apple catalog access and identity/link resolution, then enable the small music feature. Verify live grounded research with accessible links before enabling research schedules.

## Following the core release

1. Tested Web Push and notification preferences: explicit opt-in, frequency limits, quiet hours, subscription deletion, and denied-permission fallback to the existing inbox. No automatic external messages.
2. Provider health history and a rate-versioned cost ledger, with verified currency budgets and bill reconciliation; stronger-model and grounding policy controls.
3. Retrieval improvements for longer projects: managed embeddings/vector search, larger paginated browsing, OCR with a connected provider, background extraction progress and original-file export archive. Keep ownership boundaries and failed-extraction honesty.
4. Voice barge-in if supported affordably, captions and wider physical-device accessibility testing. Current pipeline is sequential and requires Stop to interrupt playback.
5. Real image generation in the proactive inbox, only after connecting a permitted provider with explicit cost/permission controls.
6. Opt-in friendship introductions from user-approved public profiles, reciprocal approval, approximate location/remote preferences, blocking/reporting. Never expose private chats or automatically contact people.
7. Separate adult dating enrollment with age assurance, reviewed reciprocal preferences, moderation and safety operations. Keep disabled until those operations exist.
8. Real mini-movie pipeline: reusable character references, storyboard, connected video provider, continuity checks, priced confirmation and downloadable generated result. A storyboard alone is not a movie.
9. Native Android assistant integration and supported iOS entry points after reviewing current platform policies. No claim of permanent PWA background microphone access.
10. Hardware companion, phone, projection and drone exploration after the software milestones; no hardware work in this release.
